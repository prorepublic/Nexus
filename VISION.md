# Vision

## What Nexus is

Nexus is a control plane for autonomous software delivery, owned and operated by a single person, running on that person's machine. The owner describes outcomes; Nexus turns them into bounded, auditable execution.

The owner's role is to provide two things: **goals** and **approvals**. Everything between those two points — planning, task decomposition, worker selection, execution, validation, repair, and packaging results for review — is the platform's job. The owner should never be a human message queue between AI tools, never copy-paste between chat windows, and never babysit a terminal.

## Principles

1. **Outcome-driven, not busywork-driven.** A Goal is a statement of what must be true when the work is done, ideally with explicit acceptance criteria. Tasks, branches, runs, and validation exist to serve that outcome and are generated by the system, not typed by the owner.

2. **Finite autonomy.** Nothing in Nexus runs unbounded. Every run has a timeout, every task has a bounded repair budget, every state change goes through an explicit hand-written state machine, and every consequential action can be cancelled. Autonomy is a budget, not a blank check. See [docs/OPERATING-MODEL.md](docs/OPERATING-MODEL.md).

3. **Evidence-based completion.** A worker claiming success means nothing. A task is complete when independent validation — file existence checks, tests, lint, typecheck, build — passes in the task's own workspace. Nexus records the evidence, not the claim.

4. **Provider independence.** Workers (Claude Code, Codex CLI, the deterministic fake worker, and future adapters) sit behind one neutral contract. Domain logic never knows which vendor executed a task. Providers can be added, removed, or swapped without touching the orchestration core. See [docs/adr/ADR-002-cli-worker-adapters.md](docs/adr/ADR-002-cli-worker-adapters.md).

5. **Local-first, secrets stay local.** The control plane, database, credentials, and source code live on the owner's machine, bound to localhost. Hybrid and remote monitoring surfaces come later and receive status and metadata only, never credentials. See [docs/adr/ADR-001-local-first-hybrid-ready.md](docs/adr/ADR-001-local-first-hybrid-ready.md).

6. **No silent spending.** Nexus runs on subscriptions the owner already pays for. Paid APIs, paid hosting, and automatic purchasing are disabled by policy and can only be enabled through an explicit owner approval. See [docs/COST-GUARDRAILS.md](docs/COST-GUARDRAILS.md).

7. **Human review is the last gate.** Goals settle to a review state, not straight to done. Merging to main, deploying, and other irreversible actions always require the owner. The platform's ambition is to make that review fast and well-informed, not to remove it.

## What Nexus is not (yet)

Deliberately deferred, so the foundation stays honest and small:

- Live model-based planning (today's planner is deterministic and rules-based).
- Automatic approval-gate creation during execution (the policy engine and approvals surface exist; the orchestrator wiring is planned).
- Notion record sync, GitHub review-comment ingestion, background daemon mode, remote monitoring.
- Voice interfaces and personal-productivity modules. These are later-phase ideas and will only be built on top of a proven delivery loop.

The roadmap with per-item status is in [docs/ROADMAP.md](docs/ROADMAP.md).
